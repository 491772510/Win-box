# MPV 内核版本注意事项

> 面向作者本人（0 代码基础，纯 Vibe coding）。**每一条命令都可以原样复制粘贴执行**。
>
> 适用范围：Windows 上给 Win-Box 用的 `mpv.exe`。**跟本仓库的代码无关** ——
> mpv 是外部程序，Win-Box 只是按固定路径找到它、把播放地址交给它。
>
> 一句话结论：**装 mpv 请认准「正式 release 构建」，别用 nightly / 带调试符号的构建。**

---

## 0. 先读这三句

1. **同一份 Win-Box 代码，换一个 mpv 版本，播放行为可能完全不同。** 遇到过「时间直接跳到最后」就是这种情况。
2. **出播放异常时，先换 mpv 版本对照，再怀疑代码。** 这比读播放器代码快一个数量级（真实教训，见第 3 节）。
3. 拿不准用哪个版本时，**优先选体积正常、带正式版号的那个**，别选体积大出一倍的。

## 1. 已知问题版本（2026-10-14 记录）

| | 出问题的构建 | 换掉之后正常 |
|---|---|---|
| 版本号 | `v0.41.0-1122-gaccb7b282` | `v0.41.0-dev-g41f6a6450` |
| 构建日期 | 2026-10-11 | 2025-12-21 |
| `mpv.exe` 体积 | **123,777,024 字节（约 118 MB）** | 57,294,336 字节（约 54.6 MB） |
| 同目录附带 | — | `mpv.pdb`（229 MB 调试符号） |

**问题构建的症状**：起播瞬间进度条直接到头、时间显示变成片尾时间、画面卡住，
几秒后提示播放结束 / 自动跳下一集。

**实测差异**（用 `--idle=yes --keep-open=yes --start=N` 启动、再 `loadfile` 加载 60 秒片源）：

| 起播点 | 问题构建 | 正常构建 |
|---|---|---|
| `--start=20`（范围内） | `time-pos = 20` | `time-pos = 20` |
| `--start=500`（超出片长） | `time-pos = 500` → **一直卡在 500** | `time-pos = 500` → **立刻回退到 0.1** |

也就是说：**正常构建发现起播点超出实际片长后会把位置拉回有效处；出问题的那个构建不会。**
位置停在无效值上，就是我们看到的「跳到最后、卡住不动」。

## 2. 怎么查自己正在用哪个版本

```bash
"C:\Program Files\mpv\mpv.exe" --version
```

输出第一行形如：

```
mpv v0.41.0-1122-gaccb7b282 Copyright © 2000-2026 mpv/MPlayer/mplayer2 projects
 built on Oct 11 2026 00:13:51
```

看两个地方就够：**`g` 后面那串 hash** 和 **`built on` 的日期**。
再顺手看一眼体积（下面这条）：

```bash
ls -la "C:\Program Files\mpv\mpv.exe"
```

- 体积 **50–60 MB** 左右 → 正常
- 体积 **100 MB 以上**，或同目录躺着一个几十上百 MB 的 `mpv.pdb` → **大概率是带调试符号的 nightly，建议换掉**

> 补充：`mpv.pdb` 只是调试符号，删掉不影响播放。但它白占几百 MB，换版本时可以一起清掉。

## 3. 播放异常的三步排查法

遇到「跳末尾 / 黑屏 / 无声 / 卡首帧」这类问题，**按这个顺序查**：

1. **换一个 mpv 版本试**（最省时间的一步，先做）
   症状消失 → 就是 mpv 版本问题，别再往仓库代码里找了。
2. 症状还在 → 换回 Win-Box 的**内置 HTML5 内核**试
   内置内核正常、MPV 不正常 → 问题在 MPV 链路（mpv 本身、或 `--wid` 嵌入、或硬解参数）。
   两个内核都不正常 → 才轮到怀疑播放地址 / 源 / 本地代理。
3. 还查不出来 → 看应用日志里 `mpv:` 开头的行（主进程把 mpv 的 stdout/stderr 原样打出来了），
   再贴给我。

**为什么第 1 步要排在最前**：mpv 的 nightly 构建是每天自动编译的开发版，偶尔会带回归。
这种回归**表现得跟应用 bug 一模一样** —— 从界面看就是「播放器坏了」，
完全看不出来是外部程序的问题。这个坑已经真实踩过一次（就是第 1 节那张表）。

## 4. mpv 从哪下载

- 官方 Windows 构建：<https://sourceforge.net/projects/mpv-player-windows/files/>
  - 进 `release/` 目录取**正式版**（文件名带明确版本号、不带 `git` 长串的那种）
  - 避开 `git/` 下面每天更新的 nightly
- 下载的是 `.7z`，用 7-Zip 解压后：

```
C:\Program Files\mpv\
├── mpv.exe          ← Win-Box 认的就是这个文件
├── mpv.com
└── ...
```

**Win-Box 找 mpv 的顺序**（`src/main/player/mpvCore.ts` 的 `resolveMpvPath`）：

1. 你在配置页「播放」里手动填的路径
2. `resources\mpv\mpv.exe`（随包内置，本仓库默认不提供）
3. 本机常见安装位置（`C:\Program Files\mpv\` 就在其中）

放在 `C:\Program Files\mpv\mpv.exe` 或填进配置页，都能被认到。
**注意**：`winget install shinchiro.mpv` 装到的是 `C:\Program Files\MPV Player\`，
不在自动探测列表里，装完还得去配置页手动填路径。

## 5. 换完版本怎么确认生效

1. 完全退出 Win-Box（含托盘 / 后台残留进程）
2. 重新启动
3. 看日志里这一行：

```
依赖: mpv=...（路径）
```

显示 `mpv=none` 说明没找到（检查路径拼写）；显示具体路径就是认到了，
该行后面的括号里会写明是「本机已安装」「随包内置」还是「自定义路径」。

> 注意：Win-Box 只在**启动时**探测一次 mpv。换完 mpv 不重启应用，用的还是旧的那份。
